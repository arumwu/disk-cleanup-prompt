請幫我做一份開發工作磁碟整理報告。掃描來源只能唯讀；你不能替我執行任何清理或刪除。

## 1. 掃描範圍

- 先確認實際作業系統與家目錄，再選擇該系統對應的位置與工具。不要假設每台電腦都是 macOS。
- 只讀取檔案／目錄中繼資料：名稱、大小、修改／變動時間、檔案類型，以及必要的程序使用狀態。不要打開被掃描檔案的內容，不讀設定、憑證、對話文字或資料庫內容。
- 例外：可以讀取之前產生的 `sizes.csv` 作比較，以及本次由你產生的報告程式、模板與驗證產物；可以用 Git 指令唯讀查詢 worktree 狀態。這些例外不能擴張為讀取其他檔案內容。
- 掃描我的家目錄，以及目前帳號可安全存取的系統暫存區。暫存區位置依 OS 與目前帳號確認，不要寫死別人的使用者名稱或暫存識別碼。
- 跳過 iCloud／其他同步雲端位置、照片圖庫、外接硬碟、其他帳號資料，以及任何可能跳出系統權限詢問的資料夾。採保守白名單；不確定時跳過並記錄原因。
- 不要求完整磁碟存取、不提權、不使用 sudo、不改權限、不掛載其他磁碟、不切換桌面或搶走焦點。
- 不追蹤符號連結、junction、reparse point 或其他可能跨越掃描邊界的連結，不下載或喚回雲端佔位檔。
- memory／memories 資料夾與明確的記憶資料檔排除，不列入清理建議；也不能透過刪除上層資料夾一起刪掉。
- 記錄已掃描與跳過範圍。不要把部分範圍的容量稱作整顆磁碟用量。

## 2. 大小與歷史比較

- 優先使用可取得的實際配置大小，說明採用的計量方式。若只能取得邏輯檔案大小，明確註記。
- 避免父子項目、硬連結等重複計算。APFS 共享區塊、稀疏檔與壓縮可能使數字不同；不要把報告大小保證成可釋放容量。
- 報告放在家目錄的 `disk-report` 資料夾；Windows 使用該帳號家目錄的對應位置。這個輸出資料夾不要算入掃描來源。
- 開始前先讀取既有 `sizes.csv`。每一輪把報告列出的項目大小追加進去，不覆蓋歷史；至少包含掃描時間、穩定項目識別碼、路徑、分類、大小 bytes。
- 使用穩定的路徑＋子分類識別項目；對話的「超過 14 天／最近 14 天」應有不同識別碼。與上次同項目比較，標出變大多少；第一次沒有基準就直說。

## 3. 分類規則

### 可以直接清

只列已能確認是可重新產生或下載的快取，而且掃描與使用狀態查核完整的項目。「可以直接清」只代表可重建，不代表你已獲授權執行刪除。

不要只因名稱包含 cache、temp、build 或 dist 就判定可刪。用途不明、仍被使用或查核失敗的項目要保留。

### 先讓我看過

對話紀錄、AI 模型、Docker 資料一律放這組。其他無法確認用途、可重建性或影響的開發資料，也放這組並說明不確定之處。

適合讓我決定的項目可以勾選；無法安全限定範圍、仍被使用或不符合條件的項目只供查看，停用勾選。開啟一般刪除選項也不能繞過這些保護。

### 作品：只標示

從名稱與目錄位置能辨識為我自己的影片專案、輸出檔、照片匯出或其他作品時，在地圖上標出是什麼，附路徑與大小；不要列入可勾選的清理建議。

若作品獨立成另一張小地圖，註明比例尺獨立，避免誤讀容量。不能只因作品放在暫存資料夾，就把它當快取。

## 4. 對話紀錄：14 天

- Codex、Claude Code 等工具的可獨立辨識對話紀錄，拆成「超過 14 天」和「最近 14 天」兩項，兩項都放在「先讓我看過」。
- 最近 14 天標「不建議刪」並停用清理。沒有符合條件的舊紀錄時顯示 0，不讓使用者勾選空項目。
- 使用可取得的最後變動時間，說清楚判斷依據；不要把它說成對話建立日期。主對話與可辨識的子對話應整組判斷，避免只刪一部分。
- 不讀內容就無法依日期拆開的 SQLite 或其他混合資料庫，整份保留、停用勾選並說明限制；不能按整個資料庫的檔案日期假裝完成逐筆拆分。
- 不刪 memory，不以刪掉整個工具資料夾來清對話。

## 5. Git worktree：四項全過才建議移除

只能在本次允許範圍內查核。四項缺一不可：

1. 沒有未 commit 的修改、未追蹤檔案或其他不明狀態。
2. HEAD 已合併進可確認的主線。若只查本機已有 ref，明說這不是遠端最新狀態；不為了這次唯讀掃描執行 fetch 或改 refs。
3. 整個 worktree 超過 7 天沒有檔案或目錄變動，不只看最外層資料夾或最後一次 commit 日期。
4. 沒有可見程序以它為工作目錄、從其中執行或開啟其中檔案。查核不完整、失敗或權限不足時，不得當成「沒有程序使用」。

Git 查詢要避免不必要的索引寫入及自訂 hook／fsmonitor 執行。主要 checkout、locked／prunable 狀態、含未查核子模組或其他不明狀態者保留。

只有通過檢查者，腳本才可以產生 `git worktree remove`；執行前必須重查。不能使用 `rm -rf`、`--force` 或刪除 Git 管理資料來繞過失敗。

每個候選都要提醒：「被 `.gitignore` 忽略、只存在這個 worktree 裡的輸出檔，也可能一起被刪。」如果能辨識出自己的作品，仍依作品保留規則處理。

## 6. 系統與 AI 暫存：3 天

- 家目錄外的系統暫存區只量目前帳號允許範圍的大小。
- 只有已確認可重建、整個候選目錄樹超過 3 天沒有任何變動，而且沒有可見程序在用的快取，才列為可以清理。其餘只計量或保留。
- AI 工具的 session 暫存，只有整個候選超過 3 天沒有任何變動的才個別列出，且一定放「先讓我看過」；較新的 session 暫存不要列成候選。
- 僅憑暫存檔名包含工具名稱，不能宣稱已確認它是 session。無法確認用途時標「用途待確認」、保留。
- 檢查子檔與子目錄的最新時間，採該 OS 能可靠取得的修改／變動資料；不要把 Windows 的建立時間誤當 Unix 的狀態變動時間。

## 7. 本機 HTML 頁面

- 不安裝新套件也能完成時，優先沿用現有工具。
- 交付可離線開啟的完整 `index.html`，不依賴外部 CDN、不上傳掃描資料、不加入追蹤。
- 左邊是按大小比例繪製的矩形樹狀圖；右邊按「可以直接清／先讓我看過」列出清單，最下面放下載清理腳本的按鈕。
- 每項顯示名稱、完整路徑、大小、刪除影響、與上次的增減，以及可勾選／保留／預設略過的原因。所有項目預設不勾選。
- 圖上小到放不下文字的項目，要能透過點選、提示或清單查看。作品只標示，不提供清理勾選。
- 顯示掃描時間、已量總量、候選量與選取量；明確區分「已選但腳本仍會略過」與可嘗試處理的容量。
- 清楚說明部分掃描、保留時間、程序查核範圍，以及查核與實際刪除間仍可能發生狀態變動。
- 只交付最終頁面的連結，不要把未填入資料的模板當報告。如果保留模板，使用不易誤開的副檔名，或讓誤開的入口導向完整報告。

## 8. 下載清理腳本，不替我執行

- 根據我的勾選產生獨立腳本，透過下載按鈕提供；不要叫我把整段腳本貼進終端機。
- 腳本開頭要求我在終端機輸入完整的 `yes` 才執行；其他輸入、輸入不可用或取消都不得清理。
- 優先使用工具自己的清除指令，例如 npm、uv、Homebrew 的清理功能。但先依本機版本確認實際作用範圍；命令若會清到未勾選的快取、安裝版本或其他資料，就不能直接使用。
- 沒有可安全限定範圍的專用指令時，腳本預設只印「略過」。需要我另外打開明確選項，才能使用 `rm -rf` 或該 OS 的一般刪除方式。
- 不產生不受勾選範圍限制的全域清理，不碰未選取的 Docker 容器、映像或 volumes，不停服務、不殺程序、不提權。
- 執行前重查目標路徑、檔案身分、時間、邊界、符號連結與程序使用狀態。掃描後新增或變動、找不到、身分改變、仍被使用或無法查核的項目，一律略過並說原因。
- 對每個 worktree 重查全部四項條件；對話與暫存重查保留天數。作品、memory、近期對話與受保護位置不能被父目錄刪除順帶清掉。
- 只處理這次選取的精確目標，不使用會掃到未選取項目的萬用字元。對包含空白、引號或特殊字元的路徑使用安全的參數傳遞，不能把路徑當 shell 程式碼。
- 工具缺失或清理命令失敗時，停止該項或略過；不能自動改用更大範圍或更強制的刪除。
- 你自己不要執行任何真正的清理命令，即使是測試也不行。

## 9. 必要驗證與交付

- 實際開啟最終 HTML 驗證：有真實掃描資料、地圖與清單能顯示、可勾選、保留項不可選、能下載腳本。不要只看 API 回傳成功或檢查模板原始碼。
