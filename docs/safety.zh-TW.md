# 判斷原則與限制

## 唯讀的邊界

掃描來源只准讀中繼資料。產生報告、腳本與 `sizes.csv` 會寫入輸出資料夾，這不等於來源遭到清理。Git 狀態查詢與讀取上次的容量紀錄，是提示詞明確允許的例外。

「只讀大小」不能保證完全沒有系統活動：作業系統、工具與背景程式仍可能更新自己的狀態。代理應避免不必要的 Git 寫入、自訂 hook、雲端檔案下載與任何權限提升。

## 保留規則優先

| 類型 | 能否成為候選 | 必要條件 |
| --- | --- | --- |
| 可重建的一般快取 | 可以 | 用途明確、範圍可限定、查核完整、無程序使用 |
| 系統暫存快取 | 可以 | 上述條件，加整棵候選超過 3 天沒有變動 |
| AI session 暫存 | 人工檢視 | 超過 3 天無任何變動；用途與使用狀態仍須查核 |
| 對話逐字紀錄 | 人工檢視 | 超過 14 天；能獨立辨識與安全選取 |
| 最近 14 天的對話 | 不建議刪 | 停用清理 |
| 混合日期的對話資料庫 | 保留 | 不讀內容就不能偽裝成已逐筆拆分 |
| memory／memories | 排除 | 不可透過上層刪除順帶移除 |
| 自己的作品與輸出 | 只標示 | 不列清理建議 |
| 模型、Docker | 人工檢視 | 不能推定可重建，不能全域 prune 未選取的資源 |
| worktree | 四項全過才可能建議 | 無未提交／未追蹤改動、已合併主線、7 天無變動、無程序使用 |

如果規則有衝突，以保留為優先。例如暫存目錄內發現作品，不應因為「超過 3 天」就刪除。設定一般刪除選項，也不能解除這些保護。

## 日期、程序與 Git 都有查核界線

最後一次 commit 日期，不能代表 worktree 最近沒有變動。最外層資料夾的時間，也不能代表所有子檔都沒變過。

程序檢查只反映可見範圍與當下狀態。查核失敗或看不到某些程序，不等於沒有程序使用。清理前須重查，使用者也應先正常關閉相關工具；腳本不應自行殺程序。

主線必須可以確認。只檢查本機已存在的 ref，不代表查到了遠端最新狀態。無法確定、含未查核子模組、locked 或其他異常狀態時，應保留 worktree。

## 工具原生指令不一定比較窄

「使用工具自己的命令」不是任意清理的通行證。有些命令會清到整個快取、所有未使用資源或舊安裝版本。實際範圍與旗標依工具版本而異，代理必須在本機確認。

如果工具命令無法只作用於使用者勾選的項目，就不能為了使用原生命令而擴大範圍。可安全限定的替代方式也沒有時，預設略過。

## 報告與腳本的最低交付檢查

- 最終 HTML 已填入資料；不是空模板或依賴無法載入的外部資源。
- 地圖與清單的容量不因父子項目重複而膨脹，且區分已量總量、候選量與選取量。
- 作品、memory、近期對話與未通過檢查的項目不能勾選，父目錄清理也不能繞過。
- 全部預設不勾選；一般刪除額外選項預設關閉。
- 下載內容只對應勾選項目，能安全處理空白、引號與特殊字元路徑。
- 輸入不是 `yes` 時不清理；未開一般刪除選項時，沒有專用指令的項目只印「略過」。
- 腳本會在執行前再次確認路徑、身分、時間、範圍與使用狀態，失敗就略過。
- 不為了驗證而真的刪檔，不用模擬成功宣稱真實清理成功。

## 公開範圍

此倉庫只包含通用提示詞、文件、授權與虛構資料示範。沒有任何人的掃描資料、對話、模型、登入資料、清理紀錄或真實截圖。

如果要貢獻案例，請重新製作虛構資料。只把帳號名稱替換掉，仍可能留下可辨識的專案名稱與路徑。
